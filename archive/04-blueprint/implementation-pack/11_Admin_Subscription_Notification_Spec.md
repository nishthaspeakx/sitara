# Admin Panel · Subscription Logic · Notification Logic

## Admin (roles: support/safety/content/finance/admin; SSO+2FA; all actions audit-logged)
Users: search (hashed lookup), state view (plan, flags, device), actions: reset, comp days, DPDP export/delete (queue, 30-day SLA). Subscriptions: gateway views, refund issue (goodwill matrix: ≤30d full), dunning states. Prompts: registry list, diff view, publish gated on green evals, staged rollout %, rollback. Persona: tone params, banned-phrase list editor (adds regression case automatically). Content: brief module templates, festival calendar editor, astro/numerology rule tables (cultural editor role). Safety centre: queue (severity sort, SLA timers), case view (redacted minimum), actions (resolve, escalate, user-care email), incident report generator, weekly FP/FN review sheet. Conversation review: ONLY flagged/user-reported; consent banner; access logged. Experiments: flag config, results readout. Costs: per-user AI spend distribution, top-1% users, model mix; alert ₹120/user/mo. Complaints/refunds/quality sampling dashboards.

## Subscription logic
States: free → trialing(7d, no card) → premium/family (monthly|annual) → past_due(3 retries/7d dunning) → cancelled(access till period end) → churned. Rules: one trial per Apple/Google/phone identity; upgrade prorates immediately; downgrade at period end; family = 1 payer + 4 invites (adults verify, minors parent-managed); India billing via Razorpay UPI/cards w/ GST invoice; US via Stripe; store-IAP fallback where mandated (iOS: subscription via StoreKit — required; web-checkout allowed where policy permits). Cancel: 2 taps, immediate confirmation, no retention offers screen (a single factual "what you'll lose" list, no guilt copy). Refunds: store policy + 30-day goodwill via support. Referral: unlock month on referee's first payment.

## Notification logic
Types: brief_ready (user-set time) · reflection_nudge (user-set, default off after 2 ignores) · family_event (T-7/T-1) · goal_checkin (weekly) · weekly_report · safety_followup (only post-crisis, consented). Decision pipeline: candidate → relevance score → daily cap check (3 default) → quiet-hours check → dedupe (no same-type <20h) → banned-copy lint → send. Ignored-twice auto-quiets that type with an in-app note ("I've stopped pinging about X — turn back on anytime"). No re-engagement guilt campaigns; win-back = one neutral email at day 30.
